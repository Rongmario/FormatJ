Found while fixing, all fixed:

- An own-line comment after `return`, `=`, or between operands became a trailing comment (S2 family). Own-line comments now always start a line.
- `keep-array-initializer-layout` chopped every element once the formatter itself had broken after `{`. It now keeps the author's rows.
- Several declarators (`int a = 1, b = 2;`) could not wrap at all.
- A fill measured a part holding forced breaks by its first line, so the second pass joined what the first had broken.
- `keep-simple-pattern-inline` read a break inside the tested expression as the author untying the pattern.
- `Outer.Inner.CONSTANT` counted as a three-link chain and could break at its dots.
- A field directly after a method got no blank line. `for (;;)` printed as `for (; ;)`.

## Bugs, must fix

### Engine

| ID  | Severity              | Bug | Repro |
|-----|-----------------------|-----|-------|
| B1  | gives up (~130 JDK files) | A trailing `//` comment is held until the next line break, so any text the layout pulls onto that line lands after the comment. Two comments join, or code is swallowed | `void m() //x` then `{ // Only a pad`, `if (a \|\| // one` then `b) // two` |
| S1  | gives up (unstable)   | A trailing comment on a token that moves to the next line (`&& // c` with `before-operator`) migrates to the end of the next line. Pass 2 no longer sees the forced break and joins the lines | `java/lang/Enum.java:218`, `PublicMethods.java:120` |
| S2  | gives up (unstable)   | An own-line comment between `=` and an array initializer becomes a trailing comment of `=`. Pass 2 then pulls `{` up | `TlsPrfGenerator.java:60` |
| B2  | gives up              | Array constructor reference not parsed | `byte[]::new`, `Class<?>[]::new` |
| B3  | gives up              | `sealed` as an identifier breaks statement parsing | `sealed = true;` |
| B4  | gives up              | Generic cast before a primitive class literal | `(Class<Object>) int.class` |
| B5  | gives up              | A UTF-8 BOM becomes an error token, so the first declaration is left verbatim | `﻿class A{}` |
| B25 | gives up              | `yield` followed by a cast or parenthesised expression parses as a call | `yield (int) (t - g());` |
| B27 | wrong output          | A block comment followed by code on the same line is held to the end of the line like a trailing comment | `f(a, /*flag*/ false, b);` becomes `f(a, false, b); /*flag*/` |
| B6  | gives up (reparse)    | Star alignment writes `*` with no space before star-less lines, so `// x` becomes `*// x` and closes the comment | `java/lang/invoke/CallSite.java` |
| B6b | corruption, uncaught  | The same pass strips the leading indentation of star-less lines inside `<pre>{@code}`. Javadoc keeps that whitespace, so the rendered sample loses its indentation. | B28 | gives up (~700 JDK files, google preset) | `javadoc.wrap` counts `@param   s` as four words and drops two words of the description. `javadoc.add-paragraph-tags` writes `<p>` on blank lines inside `<pre>` and in front of block elements | `@param   s   the detail message.` |

## Defaults for 1.0

The `formatj` preset produces output that reads worse than IntelliJ's default in common code. Fix before freezing output.

| Rule | Now | 1.0 | Why |
|---|---|---|---|
| `blank-lines.after-class-opening-brace` | 1 | 0 | Every class, interface, enum and anonymous class opens with a blank line |
| `blank-lines.before-class-closing-brace` | 1 | 0 | Same, at the close |
| `blank-lines.before-first-enum-constant` | 1 | 0 | `enum E {` + blank + `A, B` |
| `braces.empty-*-body` | `spaced` | `compact` | `class A { }`, `void m() { }`. Every mainstream style writes `{}` |
| `wrapping.closing-delimiter` | `own-line` | `attached` | `)` alone on a line, then `));` stacks. FormatJ's own `formatj.toml` already overrides it |
| `wrapping.chain-threshold` | 3 | 2 | `patterns.include(x).exclude(y)` breaks inside `exclude(` instead of at the dot |
| Assignment layout | break after `=` | break inside the value first | `files =` then `files.plus(` on the next line wastes a line and double-indents the arguments |
| Sole argument | wraps around it | hugs it | `add(` then `new Entry(` on the next line. Break inside the inner call instead |
| Inline block after wrapped header | kept | expanded | `\|\| b(c)) { run(); }` hides the body at the end of a wrapped condition |

The `google` preset pins the old values wherever google-java-format behaves that way (break after `=`, no sole-argument hug), and gains `{}` empty bodies, which gjf writes.

## Features

### New rules for 1.0

| Rule | Kind | Effect |
|---|---|---|
| `wrapping.assignment-break` | layout | `after-operator` (gjf) or `inside-value`: break after `=` only when the value's first line does not fit |
| `wrapping.hug-sole-argument` | layout | A lone call or creation argument stays on the open paren's line and breaks inside itself |
| `literals.long-suffix` | rewrite | `preserve` or `upper`. `10l` becomes `10L` |
| `literals.hex-digits` | rewrite | `preserve`, `upper`, `lower` for hex digits and the `x` prefix |
| `modifiers.remove-redundant` | rewrite | Drop `public`/`abstract` on interface methods, `public static final` on interface fields, `static` on nested interfaces, enums and records, `final` on private and static methods... only where the JLS makes it implicit |
| `arrays.c-style-brackets` | rewrite | `preserve` or `java`. `int a[]` becomes `int[] a` (fields, locals, parameters) |
| `semicolons.remove-redundant` | rewrite | Drop stray `;` between members and after a top-level type |

### Needed for 1.0

| Feature | Why |
|---|---|
| Shared discovery | One resolver (walk up, stop at `root = true`) used by the CLI, Gradle, Maven and IntelliJ. Fixes B11 and B14 |
| Shared file selection | `[files] include/exclude` in `formatj.toml`, relative to the toml's directory, used by every entry point. Fixes B12 and B13 |
| Skip ignored and generated sources by default | Hidden directories, `build/`, `target/`. The CLI run on Cleanroom picked up decompiled sources under `build/` |
| Error on empty match | Exit 2 when include/exclude patterns match no files |
| CLI range formatting | `--lines 10:20`. The core already takes ranges (`FormatRequest.withRanges`). Editors need it |

### Adoption, 1.x

| Feature | Why |
|---|---|
| Changed-only mode | `--since <ref>` in the CLI and `ratchetFrom` in Gradle/Maven |
| Spotless step | Most projects run gjf and palantir through Spotless |
| pre-commit hook | Add `.pre-commit-hooks.yaml`. Cheap |
| Machine output | `--format json` and GitHub Actions annotations for diagnostics |
| More presets | `palantir`, `aosp`, `intellij-default`, to ease migration |
| `.editorconfig` fallback | Map `indent_size`, `indent_style`, `max_line_length` and `end_of_line` |
| Maven incremental and parallel runs | The Gradle plugin is incremental and the Maven one is not |
